# Domain Specialization Bootstrap — evidence detail

> L0: Qualifying signals, audit record, deletion gates, promotion gates, and
> benchmark interpretation for domain-specialization proposals.

## Signal qualification

Signals are not votes and have no fixed threshold. Assess convergence, causal
relevance, damage, stability across changing tasks, and cheaper generic fixes.

| Signal | Qualifying evidence | Insufficient alone |
|---|---|---|
| **Repeated user steering** | The user restores the same method, gate, or evidence order across distinct tasks. | Tone, formatting, or output preference. |
| **Repeated structural failure** | Different tasks fail for the same missing domain method. | Repeats caused by one unresolved code defect. |
| **Recurring prompt scaffolding** | The same methodological scaffold is repeatedly required for competent work. | Task facts or boilerplate format. |
| **Stable evidence contract** | Authority, provenance, causal, temporal, or validity hierarchy recurs but generic SUA lacks it. | One task requesting a citation. |
| **Stable tool sequence** | Tool order is epistemically necessary despite changing content. | Convenient automation or preferred product. |
| **Unrepresented state transitions** | Valid progress depends on domain states/gates absent from generic planning and verification. | A normal software lifecycle already covered by SUA. |
| **Methodological corrections** | Corrections change how valid conclusions are reached across the family. | A correction to one fact or answer. |

A single high-damage observation may justify `COLLECT_MORE_EVIDENCE`, but an
adapter proposal requires a stable missing contract, recurrence evidence, a
bounded experiment, and failure of the generic-first counterfactual. Explain
the judgment; never convert the table into a mechanical count.

## Existing mechanism boundaries

| Mechanism | Existing contribution | Why it is not the detector alone |
|---|---|---|
| M-self-application | Finds known rules not applied to agent behavior/structure. | Requires an encountered rule, not an unrepresented contract. |
| M-learn + Add-then-Reduce | Inducts and consolidates at integration. | Does not group friction by task family or decide adequacy. |
| M-periodic-re-analysis | Compares final goal and current state. | Uses time/goal triggers rather than domain-method friction. |
| M-message-pattern-recognition | Learns recurring user-message structures. | Speech recurrence is only one signal, not proof of a method gap. |
| Layer/subproject governance | Constrains new structures and experiments. | Acts after a solution is considered. |
| SKILL_DESIGN | Incubates an already-known portable pattern. | Targets broader skills after recognition, not project adapter detection. |

## Adequacy record

Store the minimum auditable record in the consuming project:

```yaml
task_family_method:
episode_references:
generic_sua_coverage:
methodological_friction:
common_structural_cause:
missing_state_evidence_tool_contract:
generic_first_counterfactual:
counterexamples:
decision: GENERIC_SUFFICIENT | COLLECT_MORE_EVIDENCE | PROPOSE_PROJECT_ADAPTER_EXPERIMENT
proposed_adapter_boundary:
regression_and_negative_controls:
delete_when:
do_not_reopen_unless:
promotion_evidence:
```

Search by methodology and missing contract, not domain name. This record is
negative knowledge too: `GENERIC_SUFFICIENT` prevents renamed mode proposals
unless `do_not_reopen_unless` is satisfied.

## Adapter experiment contract

A proposal states only the minimum unique delta, activation boundary, baseline,
treatment, positive regressions, false-positive regressions, cost/maintenance
budget, deletion condition, and owner/project scope. It does not implement
substantive domain advice. Incubate in the project layer first; use a subproject
only if existing isolation criteria are independently met.

## Retain, revise, or delete

- **Retain** only when treatment improves the fixed domain-method criteria
  without unacceptable false activation or maintenance cost.
- **Revise** when the missing contract is correct but the activation boundary
  or evidence gate is over/under-inclusive; rerun both positive and negative
  controls.
- **Delete the adapter** when controlled regressions show no advantage, generic
  SUA absorbs its unique delta, false activation costs more than it saves, the
  domain validity method changes, or friction no longer recurs. Preserve the
  decision/reopening condition and remove active routing.

## Broader promotion

Broader promotion is not adapter retention. Require the same methodological
delta across independent projects, framework-agnostic formulation, stable
multi-context regression evidence, negative controls against mode explosion,
and explicit authorization. Portable task guidance then enters SKILL_DESIGN;
only a genuinely universal activation failure may receive the smallest
core-trigger proposal. Stop before core modification.

## Non-AI4S regression interpretation

- Debugging/incident diagnosis is a negative control: reproduce, minimize,
  root-cause, patch, and regression are already generic planning/testing
  operations unless additional stable evidence gates are demonstrated.
- Evidence-hierarchical legal work is a positive proposal case only when
  recurring jurisdiction, authority hierarchy, temporal validity, and
  binding/persuasive distinctions survive the generic-first counterfactual.
  The result is an adapter experiment proposal, not a Legal Mode.

These two fixtures test boundaries but do not prove domain-general behavior.
Controlled fresh-agent runs and unrelated task families are still
needed before `DOMAIN_SPECIALIZATION_BOOTSTRAP_VALIDATED`.
