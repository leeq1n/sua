# AI4S Phase A validation

> L0: Phase A evidence, limitations, self-audit, and project-layer promotion
> decision for AI4S Research Mode.

## Decision

**`PROJECT_LAYER_SUFFICIENT`**

The project layer is the smallest justified placement: entry documents route
new-knowledge tasks to a compact L1 controller, L2 holds conditional detail,
and regressions cover the supplied failure class. No evidence shows that this
discoverability path requires a core trigger. This is an architectural and
structural acceptance, not proof of a general behavioral effect.

Commit range: `364f231..d0f5d80`, after baseline `6e020b7`. No core-layer,
hook, agent-tool, or established P-n/M-n source changed in this range.

### Controlled behavior run

The configured provider reported HTTP **401** for every attempted baseline
call, so responses were empty. The run was rejected; a treatment arm and a
directional behavior score was not produced. The observed failure became a test:
the collector now raises on any empty response rather than writing a misleading
result. Therefore no numerical claim is made for autonomous trigger frequency,
MVP false positives, or abstraction-lift latency.

### Validator limitation

`self_health_check.py` reports FAIL. Its multi-commit parser mislabels body text
as the next title (SHA `?`), while advisory trade-off/M-n 34 checks flag recent
messages although the enforced P-n hook accepted them. This governed core tool
was not changed; the result remains yellow.

## What genuinely improved

1. Evidence states replace software phase or generic reasoning checklists.
2. Mechanism search, Reduce, lift/reset, cheap falsification, and native audit
   have automatic triggers; combination-only and renamed novelty block K4.
3. Claim types bind distinct claims to evidence gates.
4. KILL/Reduce/Lift/Reset decisions have a reopening contract.
5. Six failures are fixtures, not product knowledge; empty LLM evidence now
   invalidates an arm.

## What did not improve or remains uncertain

- A fair fresh-model A/B run is still missing because authentication failed.
- Rubric judgments remain subjective by design; the collector only validates
  completeness and reports a single run as directional.
- The ledger contract is defined but not longitudinally tested.
- All six fixtures originate from one research history; generic phrasing and
  noun-removal reduce but do not eliminate overfitting risk.
- No core trigger was tested or promoted, and no Phase B work began.
- Existing planner/harness, prompt-hygiene, and advisory self-health failures
  remain outside AI4S scope.

## Self-audit

- **P7 minimum viable**: two controller docs, one existing fixture source, one
  thin collector, and tests; no crawler, hook, core rule, or skill repository.
- **P11/P20 progressive disclosure**: 4,832-byte L1 routes; L2 is conditional;
  entry points and INDEX link both.
- **P18 regression**: six observed failure patterns plus the 401/empty-response
  failure are tests.
- **P22 replanning**: collision, saturation, and failed gates route to Reduce,
  lift, or reset instead of nearby variants.
- **P28/P29 recursion and Reduce**: SUA applied the controller to its own idea,
  rejected core promotion, kept subjective scoring explicit, and removed the
  need for multiple proposed product documents.
- **M-self-application / M-add-then-reduce**: the gap was fixed at the routing
  layer, then reduced to one L1/L2 pair plus this evidence artifact.

## Next verification, not automatic Phase B

With a valid provider, rerun both six-case arms using the committed collector,
score blindly against the fixed rubric, repeat across models/trials, and add
unrelated scientific domains. Consider a core-trigger proposal only if fresh
agents repeatedly fail to load the project-layer route. Do not edit core or
start Phase B without a new decision.
