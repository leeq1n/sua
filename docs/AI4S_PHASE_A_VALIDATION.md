## What genuinely improved

1. Evidence states replace software phase or generic reasoning checklists.
2. Mechanism search, Reduce, lift/reset, cheap falsification, and native audit
   have automatic triggers; combination-only and renamed novelty block K4.
3. Claim types bind distinct claims to evidence gates.
4. KILL/Reduce/Lift/Reset decisions have a reopening contract.
5. Six failures are fixtures, not product knowledge; empty LLM evidence now
   invalidates an arm.

## What did not improve or remains uncertain

- A fair fresh-model A/B run is still missing because authentication failed.
- Rubric judgments remain subjective by design; the collector only validates
  completeness and reports a single run as directional.
- The ledger contract is defined but not longitudinally tested.
- Six AI4S fixtures share one history; two authored non-AI4S boundary cases
  reduce but do not eliminate overfitting risk.
- No core trigger was tested or promoted, and no Phase B work began.
- Existing planner/harness, prompt-hygiene, and advisory self-health failures
  remain outside AI4S scope.

## Self-audit

- **P7 minimum viable**: two controller docs, one existing fixture source, one
  thin collector, and tests; no crawler, hook, core rule, or skill repository.
- **P11/P20 progressive disclosure**: 4,832-byte L1 routes; L2 is conditional;
  entry points and INDEX link both.
- **P18 regression**: six observed failure patterns plus the 401/empty-response
  failure are tests.
- **P22 replanning**: collision, saturation, and failed gates route to Reduce,
  lift, or reset instead of nearby variants.
- **P28/P29 recursion and Reduce**: SUA applied the controller to its own idea,
  rejected core promotion, kept subjective scoring explicit, and removed the
  need for multiple proposed product documents.
- **M-self-application / M-add-then-reduce**: the gap was fixed at the routing
  layer, then reduced to one L1/L2 pair plus this evidence artifact.
